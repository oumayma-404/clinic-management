# ClinicManagement.Domain

> The innermost Clean Architecture layer: pure C# domain model (entities, aggregates, value objects, enums, a couple of pure domain services) plus repository **interfaces**. No EF Core, no ASP.NET, no infrastructure dependencies. The `.csproj` has **zero package/project references** — the dead domain-events pipeline (its only reason for a `MediatR.Contracts` ref) was removed in `french-localization-and-cleanup`.

## Base classes & patterns (`Common/`)

- **`Entity<TId>`** (`Common/Entity.cs`) — carries **`uint Version`**, the optimistic-concurrency token EF maps
  onto PostgreSQL's `xmin` (private setter: EF owns it, the domain must never assign it). Identity-based equality (`==`/`!=`/`Equals`/`GetHashCode` by `Id`, with a runtime-type check). `Id` has a `protected set`. Generic over the id type (most use `Guid`; `User` uses `string`).
- **`AggregateRoot<TId> : Entity<TId>`** (`Common/AggregateRoot.cs`) — a bare marker base for aggregate roots (the transactional consistency boundary). Carries **no** domain-events list (the dead pipeline was removed).
- **`ValueObject`** (`Common/ValueObject.cs`) — structural equality via abstract `GetEqualityComponents()` (subclasses `yield return` their components).
- **`FdiTooth`** (`Common/FdiTooth.cs`) — static FDI tooth-number validator (`IsValid`/`IsAdult`; adult 11–48, child 51–85). Shared by `DentalRecordAct`, `TreatmentPlanItem`, and `ToothState`.

### Conventions every domain type follows
- Private parameterless ctor `private X() { }` **for EF Core**; a public ctor (or static factory) that sets `Id` and `CreatedAt = DateTime.UtcNow`.
- All setters are `private set;` — state changes only through intention-revealing methods (`Issue()`, `RecordPayment()`, `AddStock()`, `Confirm()`…).
- Invariants enforced in ctors/methods via `ArgumentNullException` / `ArgumentException` / `InvalidOperationException` (newer entities throw **French** messages).
- `CreatedAt` / nullable `UpdatedAt` are pervasive; `UpdatedAt` is bumped on mutation (often via a private `Touch()`).
- Child collections are `private readonly List<>` exposed as `IReadOnlyCollection<>`.
- **Money is TND millimes** (`decimal`, 3 decimals, away-from-zero). `InvoiceCalculator` is the single arithmetic authority; billing entities round through it.

**Core / scheduling**

| `Patient` | `Entities/Patient.cs` | Central aggregate. VOs: `Email`, `PhoneNumber`, optional `Address`, `InsuranceInfo`, `CnamInfo` (CNAM identity). Owns `Flags`, `Files`, `Appointments`, `MedicalHistoryEntries`, `FamilyHistoryEntries`. Recall/relance fields (`RecallSnoozedUntil`/`RecallReason`/`LastRecallContactedAt`) + emergency-contact fields. **`ReferredBy`** (« adressé par ») and **`Notes`/`ImportantNotes`** are free text, deliberately: the referrer is normally a practitioner *outside* the clinic so an FK to `Doctor` could not record the ordinary case, and the notes are read as a paragraph — never filtered, sorted or counted — so a child table would buy only a second write path. `ImportantNotes` is a separate column rather than a convention inside one blob because it is rendered highlighted at the top of the patient's file. Distinct from `DentalRecord.Notes`/`ImportantNotes`, which describe **one séance**. Belongs to a `Clinic`. |
| `Appointment` | `Entities/Appointment.cs` | **A declared transition table** (`AllowedTransitions` + `NextStatusesFrom`/`CanTransition`/`FrenchLabel`) is the single authority; every mutator funnels through one guard that throws a French message naming **both** statuses. Notable edges: `Completed → Cancelled` is the **only** exit from `Completed` (a visit is auto-completed by saving its fiche, so a mis-saved one used to be permanent); `Confirmed → Scheduled` is deliberately absent (`Reschedule` *preserves* `Confirmed`/`InProgress` — the A-2 fix — so it never attempts it); `NoShow → Cancelled` is kept because `CancelRecurringSeriesCommand` voids missed occurrences. `MarkVisitCompleted` returns a **`VisitCompletionOutcome`** (`Completed`/`AlreadyCompleted`/**`Contradicted`**) rather than `void`, and never throws — both callers are post-commit best-effort helpers where a throw would skip `CancelPostVisitReviewAsync` and leave the post-visit prompt nagging forever. `BookedOutsideWorkingHours` records a confirmed out-of-hours exception. State machine over `AppointmentStatus` (`Confirm/Start/Complete/MarkVisitCompleted/Cancel/MarkAsNoShow/Reschedule/Reactivate`). Optional `PatientId`; `DoctorId` is a **FK to `Doctor`** (nav property); `RecurringAppointmentId`; `GoogleCalendarEventId` for sync. **Owns `Procedures` (`AppointmentProcedure`) — a séance is several acts** — and `ProcedureTypeId`/`ProcedureDurationMinutes`/`ProcedureColorHex`/`TreatmentPlanItemId` are a **derived snapshot of the first row**, re-derived by `SetProcedures` (replace-semantics; refuses a duplicate act or a duplicate plan step). ⚠️ `SetProcedureType` now means "exactly this one act" and *replaces* the list (it preserves the plan link, which is `SetTreatmentPlanItem`'s business); use **`RefreshProcedureSnapshot`** to re-snapshot a renamed procedure without deleting the other acts. Reads that ask "which devis steps does this visit carry out?" must use **`LinkedTreatmentPlanItemIds`** (child links + the legacy scalar), never the scalar alone; `TotalProcedureDurationMinutes` is the séance's summed length. |
| `Clinic` | `Entities/Clinic.cs` | Tenant root. `Name`, `City`, contact info, unique join `Code`, `LogoUrl`. **Billing settings** (`MatriculeFiscal`, `VatApplicable`/`VatRate`, `StampDutyEnabled`/`StampDutyAmount`) frozen onto each invoice at issue. **TTN e-invoicing** toggle + `TtnEnvironment` (Sandbox/Production consts). Per-clinic **Google Calendar** (`GoogleRefreshToken`/`GoogleCalendarId`). `WorkingHoursJson` (opaque). `RecallIntervalMonths`. Owns `Users`/`Patients`/`Appointments`. |
| `Doctor` | `Entities/Doctor.cs` | Practitioner profile in a clinic. `LinkToUser(userId)` ties it to a `User`. `FullName` computed. CNAM/official-doc fields: `CodeProfessionnelSante`, `OrdreNumberCnomdt` (CNOMDT), cachet blob (`CachetStorageKey`/`CachetContentType`). Optional per-dentist `WorkingHoursJson`. |
| `User` | `Entities/User.cs` | **`AggregateRoot<string>`** — Id is the Auth0 `sub` (Cloud) or `local\|{guid}` (Local). `Role` string + `IsDoctor/IsSecretary/IsAdmin`. The closed set is now **declared** here — `RoleAdmin`/`RoleDoctor`/`RoleSecretary` + `AssignableRoles` + `NormalizeRole(value)` (canonical spelling or null) — where it used to be only a comment plus literals scattered across the policies and the two self-registration commands. **`ChangeRole(role)`** validates against it, bumps `TokenVersion` (the JWT carries the role, so the old one would otherwise stay live for the token's lifetime) and returns `false` on a no-op. It **replaced** `Update(string role, string? email = null, string? fullName = null)`, which had no caller and was a trap: the natural one-argument call assigned the two defaulted nulls and wiped the user's email and full name. Belongs to a `Clinic`. **Local-auth:** nullable `PasswordHash`, `IsActive`, `MustChangePassword`, `LastLoginAt`, lockout state (`FailedLoginAttempts`/`LockoutEnd`, 15-min `LockoutDuration`). Factory `CreateLocalUser(...)`; `SetPassword`/`UpgradePasswordHash`, `RecordSuccessful/FailedLogin`, `Activate`/`Deactivate`, `PromoteToAdmin`. Cloud users leave `PasswordHash` null. |
| `ProcedureType` | `Entities/ProcedureType.cs` | Priced procedure catalog: `Name`, `DefaultDurationMinutes` (1–479), `DefaultCost`, `Color` (`ColorHex` VO), optional `ResultingCondition` (odontogram state a matching act produces), active flag. `IsUsedByFutureAppointments(...)` guards deletion. Owns a **material list** (`ProcedureTypeMaterial`, AC-P4.9): what performing the act consumes from stock. `SetMaterials` replaces the list wholesale and refuses a duplicate item. **Opt-in** - an empty list consumes nothing, which is the majority case. It hangs off `ProcedureType` and *not* `DentalActCode` because `DentalRecordAct` has no `DentalActCodeId`, so a list there could never be consumed on fiche save (DEV-4). |
| `StockItem` | `Entities/StockItem.cs` | Inventory item, now **per-lot**. Owns `StockBatch` children (AC-P4.1) - `ExpiryDate`/`BatchNumber` used to be two scalar columns that `AddStock` **overwrote**, so a second delivery destroyed the first lot's date. `AddStock` creates a lot; `AttachExistingBatch` adds one already counted in `CurrentStock` (the migration's opening batch, so it must not increment). **`ConsumeStock` draws down FEFO** - soonest expiry first, undated lots last - and **returns the shortfall rather than throwing**: recording a visit is never blocked by a stock discrepancy, so on-hand may go negative (AC-P4.12). `RemoveStock` keeps the throwing contract for an explicit manual sortie. `SetCurrentStock` returns the **signed delta** so the caller can write the `StockMovement` AC-P4.15 requires - it returned void, which is why its only caller wrote none and the ledger stopped reconciling. `EarliestRelevantExpiry`/`HasExpiredStock`/`HasStockExpiringSoon`. |

| `Invoice` | `Entities/Invoice.cs` | Tunisian "note d'honoraires". | `Medication` | `Entities/Medication.cs` | **Per-clinic** drug catalog (`BrandName`/`Form`/`Strength`) + one-or-more `MedicationActiveIngredient` (DCI/INN). Backs the ordonnance picker. Seeded provisionally; `Update`/`ReplaceActiveIngredients`/`Confirm`. |
| `Expense` | `Entities/Expense.cs` | Clinic caisse cash-out (loyer/salaires/…): date, category, positive `Amount`, `PaymentMethod`, description. Combined with collected payments for the daily caisse/net. |
| `LabWorkOrder` | `Entities/LabWorkOrder.cs` | Bon de laboratoire/prothèse: work sent to an external prothésiste, tracked over `LabOrderStatus` (Sent→…→Fitted). Separate from the outbound `Notification`. |

## Domain services (`Services/`)

- **`InvoiceCalculator`** (`Services/InvoiceCalculator.cs`) — pure, testable Tunisian money arithmetic (no persistence). `RoundMoney` (millime, away-from-zero), `LineTotal`, and `Compute(totalHt, vatApplicable, vatRate, stampDutyAmount) → InvoiceTotals(HT, VAT, TTC)`. The single rounding authority reused by `Invoice`, `TreatmentPlan`, `Installment`, `DentalRecord`, and their lines.
- **`PaymentDateRules`** (`Application/Features/Invoices/PaymentDateRules.cs`) — the shared guard for every
  caller-supplied money date (`PaidOn`, an installment payment's, an avoir's `RefundedOn`). These reach the
  domain as non-nullable `DateTime`s, so a client omitting the key posts `0001-01-01`: the row still moves the
  collected total but is invisible in every cash window forever. A future date is the mirror image.
- **`PlanBillingRules`** (`Services/PlanBillingRules.cs`) — pure policy: **which treatment plans carry patient debt**, shared by all four money reads (« Solde patient », « Créances », la caisse, dashboard) so they can never report different figures. `DebtBearingPlanStatuses`/`CarriesDebt` (Accepted/InProgress/Completed only — a `Draft` devis is an unaccepted quote, a `Cancelled` one is void), `RepresentsItsPlan(InvoiceStatus)` (non-Draft, non-Cancelled), and two `BilledPlanIds` overloads (from loaded `Invoice`s, or from the light bridge-link tuple projection) that yield the plans a devis→facture invoice already represents. ⚠️ Since `data-and-money-integrity` these rules apply to **outstanding balances AND collected cash**. That is a
deliberate reversal of the previous note: the devis→facture bridge now carries the plan's collected payments onto
the invoice at issue, so the receipts live on the invoice track and counting the plan too would double them. The
exclusion is read-side only and self-correcting — a `Draft` bridge does not exclude, and cancelling it hands the
plan straight back to both reads.

## Repository interfaces (`Repositories/`)

Async, `CancellationToken`-aware contracts implemented in Infrastructure. Persistence is committed via the Application `IUnitOfWork` (most repos only stage changes; a few `User`/`Doctor` ones expose sync `Update`/`Remove`).

| Interface | Notable methods |
|-----------|-----------------|

## Domain Events — removed

The `Events/` folder, `IDomainEvent`, and `AggregateRoot`'s event list were removed (`french-localization-and-cleanup`): a dead "parallel-universe" pipeline (`SaveChangesAsync` never drained events; zero handlers). Side effects (in-app `StaffNotification`s, SMS/WhatsApp reminders) are produced **inline, post-commit** from the command handlers via `INotificationGenerator`/`IReminderScheduler`.

## Gotchas
- `User` is keyed by **string** — the Auth0 `sub` (Cloud) or `local\|{guid}` (Local) — unlike all other `Guid`-keyed types.
- `Appointment.PatientId` and `DoctorId` are optional: an appointment can be a "blocked"/occupied slot with no patient. `DoctorId` is a real FK to `Doctor` (not free-text). In-app notifications are only generated for patient-bearing events and never for the actor.
- **Denormalized snapshots are intentional, not FKs**: `Appointment` snapshots procedure duration/color; `DentalRecord` derives its summary/cost/teeth from its acts; `InvoiceLine`/`TreatmentPlanItem` snapshot `CodeActe`; `MedicalDocument` snapshots patient/clinic/doctor.
- **CNAM/DCH/medication catalogs are per-clinic** (each has `ClinicId` and a `HasQueryFilter`; every clinic is seeded the same default set, then edits stay private). ⚠️ Their in-source class/interface docstrings still say "global reference data (no ClinicId)" — that wording is stale; trust the `ClinicId` property + query filter.
- Money everywhere is TND **millimes** (3 decimals). Round only through `InvoiceCalculator`.
- `ColorHex`'s curated palette must stay in sync with the frontend `COLOR_PALETTE`.
- `ClinicReminderSettings` and `NotificationRead` are the two non-standard keys: the former's `Id` **is** the clinic id (1:1 shared PK); the latter is a plain composite-key class, not an `Entity`.
