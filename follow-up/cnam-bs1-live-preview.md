# Embed the real BS1 in the document-editor preview

> **Type:** enhancement
> **Priority:** medium
> **Created:** 2026-07-20
> **Feature:** cnam-bs1-official-overlay
> **Next step:** run `/define-small-feature` (design decision + non-trivial FE work — not a quick-fix)

## Problem
For `documentType === "bulletin-cnam"`, the document-editor right-panel preview
(`web/components/document-editor-content.tsx:1819+`) renders the **generic letterhead
document** used by every other type ("Paris, le…", generic patient block, custom acts summary).
It does **not** resemble the official BS1 that is actually generated by `CnamBs1BulletinRenderer`,
so what the user sees while filling the form does not match the downloaded PDF. The user asked to
"see the actual CNAM BS being filled" in the preview.

## Why this is not a quick-fix
It needs a **design/UX decision** and more than a surgical edit:
- **Chosen direction (user, 2026-07-20):** embed the *real* generated BS1 PDF in the preview pane
  (e.g. call `medicalDocumentsApi.generatePdfForDownload(buildDocumentData())`, show the returned
  blob in an `<iframe>`/`<embed>`), so the preview is byte-identical to the download.
- Open design questions to resolve in `/define-small-feature`:
  - **Trigger:** live/debounced regeneration on each edit vs. an explicit "Aperçu BS1" button
    (generating on every keystroke is expensive — the renderer opens the PDF + stamps every field).
  - **Scope:** only swap the preview for `bulletin-cnam`, leaving the generic preview for the other
    four document types unchanged.
  - **States:** loading, generation-failure (reuse the AC-6 French message), and the empty/no-patient
    case.
  - **Perf:** cancel in-flight generations; revoke object URLs to avoid leaks.

## Key Files
| File | Relevance |
|------|-----------|
| `web/components/document-editor-content.tsx` | Preview panel (`1819+`), `buildDocumentData`, `generatePdfForDownload` |
| `web/lib/api/*` (medical documents module) | `generatePdfForDownload` client call |
| `api/.../Services/CnamBs1BulletinRenderer.cs` | The renderer whose output the preview should mirror |

## Out of scope
The two other issues reported alongside this were fixed directly (quick-fix, 2026-07-20): the malade
date-of-birth now shows the DOB (not the age) on both PDF paths, and the acts-table text auto-fits its
column so wide values no longer overlap the next column.
