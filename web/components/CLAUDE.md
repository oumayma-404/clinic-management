# web/components/ — Feature Components & UI Primitives

Feature/screen components for the clinic frontend; `components/ui/` holds shadcn/ui primitives. All feature components are client components. Most fetch through `lib/api/*`, surface errors via `sonner`/`lib/errors`, and subscribe to `useClinicRealtime` for live refresh. Money is French/Tunisian via `lib/format` (`formatDT`, `formatDateFr`).

## Conventions

- **A card header's icon goes in a tinted chip**, not in the same ink as the text beside it. `size-8 rounded-lg` + a 12 % wash + the matching ink (`bg-primary/10 text-primary`, a `zoneChipClass(ZONES.x)`, or a semantic `-wash`/ink pair when the card's subject really is a state). `app/documents/page.tsx` is the reference and `appointment-list.tsx` the sized-down template. A black glyph next to black text is not an icon, it is more text — 43 headers drawn that way were the largest single reason the app read as grey. **Not every card**: only ones that are a named section of a page with its own identity, never inside a dialog (the dialog title already names it) and never where the icon already carries a status colour.
- **Colour is expressed in tokens, never in palette literals.** `text-success` / `bg-success-wash` · `bg-warning-wash` + **`text-warning-ink`** (never `text-warning` on its own wash — it lands near 3.5:1) · `text-destructive` / `bg-destructive-wash` · `text-primary` / `bg-primary/10` · `text-muted-foreground` / `bg-muted/40` / `border-border`. Because a token already carries its dark value, converting a pair means **deleting the `dark:` twin** — that removal is most of the point, since a hand-maintained dark mode is what drifts. Genuinely categorical colour (tooth conditions, the act-colour picker) is *data*, not theme, and stays.
  ⚠️ **`bg-accent/30/10` is not a class.** Tailwind does not parse a double opacity modifier, so it emits nothing at all — four of these shipped, and one of them was the only thing distinguishing an enabled working day from a disabled one. Grep for `/[0-9]+/[0-9]+` in class strings.
- **`ui/stat-strip.tsx` is the ONE summary strip** — the row of figures over a list, on `/caisse`, `/factures`, `/cheques` and `/rappels`. `StatStrip` derives its column count from its cells and wraps `dashboard/kpi-grid.tsx`, so the surface, the hairlines and the filler cells stay in one place; `Stat` is a cell (small uppercase label · optional glyph · `text-xl` figure · optional hint), and `onSelect` turns it into a filter control with a 2 px `STATUS_TONE_RAIL` on the selected one. Four screens used to draw this object four ways — `text-2xl` on white with a decorative blue dot (caisse, factures), a small uppercase label with an icon (chèques), and **four edge-to-edge `-wash` tiles** (rappels) that read as a traffic light — breaking to 4-up at three different widths between them. ⚠️ **A `tone` colours the figure and its glyph, never the cell and never the label**: colouring the label too was tried and it is the filled tile again with the fill taken out. ⚠️ `text-xl` flat, deliberately not `KpiCard`'s `text-xl sm:text-2xl` — that is a *link with a period comparison* and earns the step; a strip is raw figures over the table that is the actual content, and `text-2xl` there is what « trop balky » named. It is also what keeps 320 px safe: « 19 460,000 DT » measures ~100 px against a ~112 px cell.
- **`ui/status-tone.ts` serves a tone in four shapes, and a feature maps its own statuses onto it rather than holding colours.** `STATUS_TONE_CLASS` (wash + ink, for a pill or a tinted tile) · **`STATUS_TONE_INK`** (ink alone, for prose or for a figure already sitting on the right wash — a second wash over a correct one reads as a smudge) · **`STATUS_TONE_RAIL`** (the full-strength hue as a raw `var(--success)` for an inline `backgroundColor`: a row stripe, a card rail, a meter fill — at wash strength a hairline is simply not there) · **`STATUS_TONE_RING`** (`ring-success` &c., paired with `ring-2 ring-inset`, for a surface that is *selected* rather than merely tinted; a ring colour with no width paints nothing, so it is safe to apply unconditionally and toggle only the width). `components/rappels/delivery-tone.ts` is the reference for the feature half — one `Record<Status, StatusTone>` — and it exists because that page carried **four** parallel colour maps that could disagree about what « bloqué » looks like. ⚠️ **Raw tokens in the rail map, utilities in the ring map, and the difference is not cosmetic**: the `--color-*` aliases are `@theme inline` entries that Tailwind emits to `:root` only when it judges them *used*, so a `var(--color-success)` in an inline style is a coin flip that paints **transparent** when it loses — silently, since an unresolvable custom property is not an error. Utilities are generated from the theme key and are always fine.
- **`ui/table.tsx` cells WRAP, and that is what keeps a table inside the screen.** The primitive used to put
  `whitespace-nowrap` on every `TableHead`/`TableCell`, so a table's intrinsic width was the sum of its longest
  *unbreakable* value and no column could compress: one free-text column set the width of the whole surface and
  pushed the rest out of the scrollport. Measured signed-in, `/caisse`'s ledger rendered **1563 px inside a
  1084 px box on a 1440 px laptop** — « Mode », « Entrée », « Sortie » and « Solde » simply absent — because
  « Libellé » (495 px) and « Mode » (323 px) hold sentences; `/stock` hid 254 px and `/waiting-list` 161 px at the
  same width. The reader's only clue was the container's 24 px fade, so those columns read as non-existent rather
  than as off-screen. Four separate workarounds had grown around that default — the fade, `TableEmptyRow`'s
  `sticky w-[100cqi]`, `CARDS_ONLY_LG`, and a hand-added `whitespace-normal` in `reminder-log-table` — and all
  four were treating the symptom.
  Pass **`whitespace-nowrap` at the call site** for a value that must stay atomic (a `d MMM yyyy` date, a phone
  number, a `F-2026-0142` reference — those break at their spaces and hyphens like any other text); **`numeric`**
  already implies it, along with `text-right` + `tabular-nums`. Pass **`clamp`** on a free-text column to cap it
  at two lines with the full value in the cell's `title` — opt-in, never the default, because it needs
  `display: -webkit-box`, which would flatten an action column's flex row of buttons.
- **A page's controls go through `PageHeader`'s own `actions` slot — never a hand-rolled flex row around `<PageHeader>`.** As a flex item beside a sibling the header shrinks to its title's width, so the controls bunch against the heading instead of sitting at the page's far edge where every other screen puts them. Five pages had it — `/caisse`, `/stock`, `/lab-orders`, `/waiting-list`, `/recurring-series` — each having reinvented the row `actions` already is (it is `flex flex-wrap`, so it wraps below `sm:` exactly as those wrappers did). `check:responsive`'s **`page-header-not-a-flex-item`** fails the gate on it.
- **`flex-1` is `flex: 1 1 0%`, and that basis beats a `w-full` beside it.** A child meant to take a row of its own below `sm:` must therefore *not* carry an unprefixed `flex-1`, or its hypothetical size is zero, it never triggers the wrap, and it collapses to whatever its siblings leave (measured: `ui/list-toolbar.tsx`'s search box at **4 px** on `/fournisseurs` at 390 px). Prefix the `flex-1`, or give the child a real `basis-*` below the hinge — `subscription-banner.tsx`, `list-toolbar.tsx` and `doctor-working-hours-card.tsx` all carry the same correction.
- Dialogs/modals are controlled (`open` + `onOpenChange`) and report success via callbacks; parent tables reload via a bumped `reloadKey`/`reloadToken` **and** `useClinicRealtime`.
- Components fetch through `lib/api/*`, format money/dates via `lib/format`, and surface errors via `lib/errors`/`sonner`.
- Confirm-destructive flows use `ui/alert-dialog`, and the confirm button takes **`variant="destructive"`** — `AlertDialogAction` used to render `buttonVariants()` unconditionally, so every destructive confirm had to remember a `className` and two forgot, shipping a blue « Détacher la fiche » / « Désactiver » beside an outline « Retour » where the irreversible option read as the recommended one. A confirmation must also **name what it destroys** (« Supprimer le brouillon de {patient} ? » / « Le devis du {date} — {montant} … »), not « Êtes-vous sûr ? »: with three drafts open, a generic dialog cannot tell you which one you are about to lose. Blob downloads use `lib/download`.
- **A failed read must never render as empty data.** `.catch(() => [])` turns a network error into « Aucun antécédent médical » — which, on the screen a dentist checks for allergies before injecting, is a confidently wrong answer rather than a missing one. Record *which* read failed and render a per-section « … n'a pas pu être chargée. » + « Réessayer » beside the sections that did load.
- Admin-gated surfaces read `useSession().user.role === 'admin'`; local-only surfaces also check `mode === 'local'`.
