# web/components/ — Feature Components & UI Primitives

Feature/screen components for the clinic frontend; `components/ui/` holds shadcn/ui primitives. All feature components are client components. Most fetch through `lib/api/*`, surface errors via `sonner`/`lib/errors`, and subscribe to `useClinicRealtime` for live refresh. Money is French/Tunisian via `lib/format` (`formatDT`, `formatDateFr`).

Without the badge, four acts on the same date read as four visits. | `treatment-plans/plan-timeline.tsx` | « Parcours » — a chronological feed (created / accepted / séance planifiée / acte réalisé / paiement encaissé / annulé / facturé) built only from fields already on `TreatmentPlanDto`. Reuses `notification-panel.tsx`'s feed shape rather than inventing a timeline primitive. |
| `treatment-plans/plan-progress-bar.tsx` | Hand-rolled `role="progressbar"` (no `progress.tsx` primitive, no `@radix-ui/react-progress`). Renders **nothing** at 0 acts rather than a zero-width bar. Used by the workspace, and by `plan-act-pips` as its **long-plan fallback** — it is no longer the patient band's primary progress display, because "nothing at 0 *acts*" still left a full-width grey slab at 0 *done*. |
| `treatment-plans/plan-act-pips.tsx` | One pip per planned act, coloured by its derived état (`planItemState`). Encodes **four** states — réalisé / séance planifiée / séance passée sans fiche / à planifier — in less width than a bar needs for one, and keeps meaning at 0 réalisé, where a bar degenerates into a grey slab. Acts stay in **plan order**, not sorted by état: the API orders them by `sequenceNumber`, and a plan whose 1st and 3rd acts are done while the 2nd is not is telling you something got skipped. Falls back to `PlanProgressBar` + fraction past **12** acts (a row of eighteen dots is a smear). Pips are `aria-hidden`; the text fraction carries the accessible value — which is *why* they replaced the progressbar role, whose `aria-valuemax` of 0 announces as undefined progress. Per-état treatment is an **inline `boxShadow` map, not Tailwind arbitrary values**: the ring widths differ per state and one needs a palette colour, which in v4 is `var(--color-amber-500)` — v3's `theme(colors.amber.500)` resolves to nothing and renders an *invisible* pip rather than an obviously broken one. |
| `treatment-plans/patient-plans-strip.tsx` | The patient page's treatment **band** above the tabs (`border-y`, no card — ~76 px, replacing the ~250 px `patient-plan-card.tsx`): lead plan + statut + révision + « Facturé », the **counted** next action as the headline (`planHeadline`, e.g. « 1 acte à enregistrer » — the only line that says what to *do*, and it re-derives as visit times pass), then pips · Reste · prochaine séance · status chips. Four defects of the card it replaced, each fixed: the 0 %-progress grey slab; « 0/2 actes réalisé » (the participle was pluralised on `itemsDone`, not the noun); « Reste » never shown though it is the money question staff have; and `Completed`/`Cancelled` plans filtered out of « +N autres », which made finished treatment **unrepresentable**. Renders null only with zero plans. « Reste » turns `destructive` once the acts are done but the money is not. Design + mockups in `features/patient-plans-summary/`. |
| `treatment-plans/plan-next-action.ts` | Pure helpers: `planItemState` (the four états), `isPlanBilled`, `planNextAction`, `leadPlan`. No I/O. |
| `treatment-plans/treatment-plan-form-modal.tsx` | ⚠️ **A plan is validated and numbered on creation**, so **amend mode is the only editor a devis ever gets** — and everything the endpoint accepts is now sent: acts corrected **in place** (`updateItems`, id preserved so appointment/fiche links survive), additions, removals, the échéancier, the title and the notes. | `treatment-plans/installment-payment-modal.tsx` | Record an installment (échéance) payment + receipt. |
| `treatment-plans/revise-installments-modal.tsx` | Re-spread an accepted devis's échéancier (`PUT /treatment-plans/{id}/installments`) without touching the acts. ## components/ui/ — shadcn/ui primitives

Standard shadcn/ui (new-york) wrappers over Radix + CVA + `cn()`. Treat as the design-system layer:

`alert-dialog`, `avatar`, `badge`, `button`, `calendar`, `card`, `checkbox`, `command`, `dialog`, `dropdown-menu`, `input`, `label`, `popover`, `radio-group`, `select`, `separator`, `sheet`, `switch`, `table`, `tabs`, `textarea`, `tooltip`.

Add new primitives with the shadcn CLI (`web/components.json`, base color neutral, CSS vars, lucide icons).
⚠️ The current CLI emits imports from the **`radix-ui` umbrella package**, which this project does not depend on. Rewrite a freshly-added primitive's import to the scoped package that is already installed (e.g. `@radix-ui/react-dialog` for `sheet`, `@radix-ui/react-radio-group` for `radio-group`) and revert the CLI's `package.json`/lockfile edit — `sheet` and `radio-group` were added this way and add **zero** dependencies.

Non-shadcn additions to the same layer:
- **`form-error-banner.tsx`** — the shared `aria-live` refusal banner used by the dialogs.
- **`confirm-by-typing-dialog.tsx`** — a destructive confirm the operator must **type** a phrase to unlock (AC-P3.47). It exists because the repo's single two-button `AlertDialog` is used for everything from deleting a procedure type to deleting a patient, so an irreversible multi-table operation (anonymise, finalise a bordereau) had no way to *feel* different from the dialog dismissed twenty times a day. Deliberately a plain `Button` rather than `AlertDialogAction`, so a failure leaves the dialog open with the typed phrase intact.

## Conventions

- Dialogs/modals are controlled (`open` + `onOpenChange`) and report success via callbacks; parent tables reload via a bumped `reloadKey`/`reloadToken` **and** `useClinicRealtime`.
- Components fetch through `lib/api/*`, format money/dates via `lib/format`, and surface errors via `lib/errors`/`sonner`.
- Confirm-destructive flows use `ui/alert-dialog`. Blob downloads use `lib/download`.
- Admin-gated surfaces read `useSession().user.role === 'admin'`; local-only surfaces also check `mode === 'local'`.
