# web/components/ — Feature Components & UI Primitives

Feature/screen components for the clinic frontend; `components/ui/` holds shadcn/ui primitives. All feature components are client components. Most fetch through `lib/api/*`, surface errors via `sonner`/`lib/errors`, and subscribe to `useClinicRealtime` for live refresh. Money is French/Tunisian via `lib/format` (`formatDT`, `formatDateFr`).

## Appointments

| File | What it renders / does |
|------|------------------------|
| `appointment-list.tsx` | Dashboard "Rendez-vous du jour" — API-wired via `useAppointments`; hides Cancelled/NoShow. |
| `appointment-calendar.tsx` | Day/week/**month** calendar; optional `doctorId` filter + show-cancelled/completed toggles. Per-card "non synchronisé" badge + "Push to Google" gated on `useConnectivity().internetReachable`; push → `googleCalendarApi.syncAppointment`, `onChanged` refetch. **Since the agenda density pass it owns the whole desktop/tablet agenda bar in ONE row** — nav, date + window total, Aujourd'hui, the view switch, the praticien Select (visible from `xl:`, inside « Filtres » below it), a « Filtres » popover holding the two status switches *and* the legend, a « ⋯ » popover holding Exporter and the admin Google actions, and « Nouveau ». It used to be four rows across two files (two here, two in `app/appointments/page.tsx`), ≈ 215 px, which left a ~910 px window showing five hours of an eleven-hour day and put an administrative Google row between the date and the view switch. The page's four controls now arrive as props (`onNewAppointment`, `doctorFilter`, `googleControls`) because this component already owns everything that bar is made of: the export window, the appointment index and the view-aware date arithmetic. ⚠️ The row is `flex-nowrap` and the **title absorbs the slack** (`min-w-0 flex-1 truncate`) — that is what makes 820 px safe, where the 256 px rail leaves ~532 px and a wrap would be a third row on the device this product is used on most. |
| ↳ **`gridWindow`** | **The time grid renders the clinic's open hours, not 0–23.** The old grid rendered all twenty-four rows and merely *shaded* the closed ones, so two thirds of the scroll was dead travel and — since the initial scroll centres on "now" — the morning sat permanently above the fold. ⚠️ **It is a union, not a filter** (§ 0): the window covers the configured hours **and every appointment booked in the visible days**, so a 06:30 emergency or a visit running past closing *extends* the grid instead of vanishing from it; a « Afficher les 24 heures » disclosure covers booking *into* a closed hour. ⚠️ `gridWindow.fromHour * 60` is subtracted in exactly two places — `renderAppointmentBlock`'s `top` and the scroll effect's fallback — and **nowhere else**: the current-time line asks the DOM for its row's `offsetTop`, so it re-bases for free. ⚠️ **The current hour is part of the union, and it is load-bearing, not tidiness.** The line reads its position off the DOM row for the current hour, so trimming made that row *conditional* — this clinic opens 09:00–17:00, so from 17:00 every evening the query found nothing and the `else setCurrentTimePosition(null)` that a trimmed grid genuinely requires **deleted the « maintenant » line**. `nowHour`/`nowHour + 1` widen the window whenever today is on screen, so the line always has a row to sit in. ⚠️ And the two effects that key off the window take **`gridWindow.fromHour` / `.toHour`, never the object**: « maintenant » rebuilds it every time the wall-clock hour turns, so an object dependency would fire a `scrollTo` on the hour, every hour, dragging the agenda off whatever the user was reading. The line itself spans the **full grid width**, gutter to right edge, as it always has — the density pass scoped it to today's column and that was reverted on request. The block also drops the `NNm` badge (its **height** states the duration — the phone branch always said so) for the start time + act name, today's **column** is tinted rather than just its date pill, and each weekday header carries its own RDV count (« fermé » on a closed day, never « 0 »). |
| ↳ **`agenda-grid-drag.ts`** | **The two pointer gestures a calendar is expected to have** (`agenda-grid-gestures`): drag across empty hours to book a span, drag a block to move it. `useAgendaGridDrag` owns the gesture and nothing else — no fetching, no geometry constants, no rendering — so the hour window, the phone's taller rows and the week's column bands stay in the calendar. ⚠️ **Targets resolve through `elementFromPoint` + `dataset`, not per-cell handlers**: a week grid has 168 cells and a move may cross day columns, and it is the only shape that also answers « the pointer is over no cell at all » — the release-outside case, which must **cancel** rather than reuse the last cell. That makes the attribute names a contract between two files no type can see, so `check:responsive`'s **`agenda-gestures`** derives the required set from the hook's own `dataset` reads *and* asserts every cell calling `beginCellGesture` also spreads `cellDataProps`. ⚠️ **Touch arms on a ~350 ms long press, a mouse on 4 px of movement** — the same container scrolls 24 hours *and* hosts the Jour day-swipe, so a gesture starting on contact would take the thumb from both; past 10 px before the timer the touch is a scroll and the gesture is abandoned outright, never re-armed. Once armed, a **non-passive `touchmove` `preventDefault`** is the only thing that stops the day scrolling — setting `touch-action` mid-gesture is ignored by every engine, so the class-based version compiles, reads correctly and does nothing. ⚠️ It deliberately does **not** claim the plain tap on a block: the phone block is a real `<button>`, so Enter/Space produce a `click` and no pointer events at all, and the block keeps its own `onClick` guarded by `didConsumeGesture()` — which the day-swipe reads too, since `touchend` fires *after* `pointerup`. ⚠️ `select-none` on the scroller is **unconditional**: the browser anchors a text selection on `mousedown`, before any movement has said this is a drag, so gating it on the armed state lands the class after the smear already exists (measured, not assumed). |
| ↳ the grid's **empty state** | « Aucun rendez-vous cette semaine » is a quiet line in the **footer strip**, not the `inset-0` card it used to be. That card read as a modal, sat on top of the hours the user was trying to click, and — once the grid also answered to a drag across those hours — covered the whole gesture. The strip therefore renders whenever the range is empty, not only when the hour window is trimmed, and is suppressed while `loading` **or** `error` is set, so a failed fetch is never reported as a free day. The overlay's own « Nouveau rendez-vous » button went with it: the action already has two homes (the agenda bar, and the phone's floating action). |
| `appointment-acts-picker.tsx` | **« Actes du rendez-vous »** — the séance's act list, shared by both booking dialogs. Replaces the single « Type d'acte » Select each carried, which is why the second and third act of a visit could only be typed into the notes. Searchable Popover+`Command` (a clinic's catalogue is too long for a Select) with **one `CommandGroup` per clinical discipline** (`procedure-categories.ts`) — `cmdk` hides a fully-filtered group, so typing collapses this back to a flat ranked list for free. ⚠️ The discipline is joined into each item's `value`, since cmdk matches on `value` alone: without it the headings would be searchable to the eye but not to the keyboard. « Acte personnalisé… » sits in its **own** group, so creating an act is not filed under whichever discipline happens to come last. Removable rows, a live `n actes · N min` badge, and the inline « acte personnalisé » creation — which only the *create* dialog had, so sharing gave it to both. A picked act stays **visible and ticked** rather than filtered out (vanishing reads as "it failed"), a row whose procedure left the catalogue is **kept and marked** (silently dropping it would delete an act from a booked visit), and `totalActsDuration` is the one implementation of the summed length. |
| `create-appointment-dialog.tsx` | Create RDV (patient, **several acts**, doctor, date/time, duration). Advisory `useAppointmentOverlap` warning; phone validation. ⚠️ **`performCreate` is re-entered by design and must therefore be idempotent about the patient** — the past-time, slot-taken and duplicate-patient confirmations all re-submit it. It used to call `patientsApi.create` on every pass, so one « créer quand même » on a taken slot put the new patient on `/patients` **twice**; `createdPatientIdRef` now holds the committed id and the retry books onto it. The three overrides travel as one **merged** `CreateOverrides` object (`hours`/`overlap`/`duplicatePatient`) rather than positional booleans, because a booking can trip all three and each confirmation must not un-grant the last; a fresh `handleSubmit` resets them, the created id survives until the dialog closes. Once that id exists the new-patient fields and the « Nouveau patient » switch go **read-only** behind a `role="status"` note — the record is committed and this form cannot reach it, so letting the name drift would silently produce the second patient the ref exists to prevent. The « Ce patient existe peut-être déjà » prompt is the server's `patient_duplicate` refusal shown verbatim; its **destructive** action is « Créer quand même » and its cancel switches back to the patient picker (a duplicate cannot be merged — closing costs nothing). Takes **`presetPlanActs: PresetPlanAct[]`** (was a single `presetPlanItemId`): one entry books a step, several book them *together*, each keeping its own devis link. A plan act whose procedure does not resolve is seeded as a **link-only** row, not dropped. Duration follows the acts' sum until the user sets it by hand (`durationTouched`) — or until a caller supplies **`defaultDurationMinutes`**, which arrives with `durationTouched` already **true**: a span dragged across the agenda's hours is as explicit a statement about length as typing the number, so the first act picked must not silently replace it with the catalogue's 30 minutes. The page clears it on every non-drag door into the dialog, since one long-lived instance would otherwise carry the last drag's length into the next click-booked visit. |
| `edit-appointment-dialog.tsx` | Edit/cancel/complete an RDV (confirm AlertDialog); overlap warning; the same acts picker. Hydrates from `procedures`, falling back to the lead-act scalar for an older response — without that fallback the first save would persist an empty list over a real act. `durationTouched` starts **true** on hydration: a booked visit's stored length is already someone's decision, so merely opening it must not relengthen it. |

| `patient-record-modal.tsx` | **Confirm-first** dental-record entry, one 780px column read top-to-bottom: alerts → meta → the act (`ActSlot`) → the full-width `RecordToothChart` → three `RecordSection`s → totals footer. ## Conventions

- **A card header's icon goes in a tinted chip**, not in the same ink as the text beside it. `size-8 rounded-lg` + a 12 % wash + the matching ink (`bg-primary/10 text-primary`, a `zoneChipClass(ZONES.x)`, or a semantic `-wash`/ink pair when the card's subject really is a state). `app/documents/page.tsx` is the reference and `appointment-list.tsx` the sized-down template. A black glyph next to black text is not an icon, it is more text — 43 headers drawn that way were the largest single reason the app read as grey. **Not every card**: only ones that are a named section of a page with its own identity, never inside a dialog (the dialog title already names it) and never where the icon already carries a status colour.
- **Colour is expressed in tokens, never in palette literals.** `text-success` / `bg-success-wash` · `bg-warning-wash` + **`text-warning-ink`** (never `text-warning` on its own wash — it lands near 3.5:1) · `text-destructive` / `bg-destructive-wash` · `text-primary` / `bg-primary/10` · `text-muted-foreground` / `bg-muted/40` / `border-border`. Because a token already carries its dark value, converting a pair means **deleting the `dark:` twin** — that removal is most of the point, since a hand-maintained dark mode is what drifts. Genuinely categorical colour (tooth conditions, the act-colour picker) is *data*, not theme, and stays.
  ⚠️ **`bg-accent/30/10` is not a class.** Tailwind does not parse a double opacity modifier, so it emits nothing at all — four of these shipped, and one of them was the only thing distinguishing an enabled working day from a disabled one. Grep for `/[0-9]+/[0-9]+` in class strings.
- Dialogs/modals are controlled (`open` + `onOpenChange`) and report success via callbacks; parent tables reload via a bumped `reloadKey`/`reloadToken` **and** `useClinicRealtime`.
- Components fetch through `lib/api/*`, format money/dates via `lib/format`, and surface errors via `lib/errors`/`sonner`.
- Confirm-destructive flows use `ui/alert-dialog`, and the confirm button takes **`variant="destructive"`** — `AlertDialogAction` used to render `buttonVariants()` unconditionally, so every destructive confirm had to remember a `className` and two forgot, shipping a blue « Détacher la fiche » / « Désactiver » beside an outline « Retour » where the irreversible option read as the recommended one. A confirmation must also **name what it destroys** (« Supprimer le brouillon de {patient} ? » / « Le devis du {date} — {montant} … »), not « Êtes-vous sûr ? »: with three drafts open, a generic dialog cannot tell you which one you are about to lose. Blob downloads use `lib/download`.
- **A failed read must never render as empty data.** `.catch(() => [])` turns a network error into « Aucun antécédent médical » — which, on the screen a dentist checks for allergies before injecting, is a confidently wrong answer rather than a missing one. Record *which* read failed and render a per-section « … n'a pas pu être chargée. » + « Réessayer » beside the sections that did load.
- Admin-gated surfaces read `useSession().user.role === 'admin'`; local-only surfaces also check `mode === 'local'`.
